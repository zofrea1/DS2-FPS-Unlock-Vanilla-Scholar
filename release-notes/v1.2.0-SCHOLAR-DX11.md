# Dark Souls II: Scholar of the First Sin, FPS Unlock v1.2.0

High-FPS unlock with gameplay physics fixes. Files: `xinput1_3.dll` and `DS2-FPS-Unlock.ini`, next to `DarkSoulsII.exe`. This is the 64-bit Scholar of the First Sin build; the original Dark Souls II uses the Vanilla (DX9) release.

## New in 1.2.0
- **A built-in frame cap** (`FPSLimit`, default 0 = uncapped). RTSS or the NVIDIA control panel are no longer needed. The gameplay fixes step at the capped rate, a frame that already ran long is not delayed, and a hitch does not make the next frames rush. `FPSLimitPoint` chooses where the cap waits:
  - `present` (default): just before the picture is shown. The steadiest frame pacing while the game is reaching the cap.
  - `early`: at the start of the frame, before the controller is read. The lowest input delay, and the better choice on a variable refresh rate (VRR) display. If this build of Scholar does not have that point, the cap waits before the picture instead and the log says so.
- **Exclusive fullscreen is no longer held at 60 FPS.** The game asked for a 60 Hz mode with vsync, which held fullscreen at 60 (on the Steam Deck even with the screen at 90 Hz). Fullscreen now asks for your desktop's refresh rate (`FullscreenRefreshRate`, 0 = the desktop's) and presents without waiting. `VSync = true` waits for one vblank at that rate instead: tear-free, with the frame rate following the screen unless `FPSLimit` is lower. If the display refuses the raised rate, the game's own is used.
- **16:10 and other screens fill in fullscreen** (`FixAspect`, on by default, works with or without `FPSUnlock`). Fullscreen used to draw a 16:9 picture between black bars. It now fills the screen as a window does, with the HUD at its usual size at the screen edges. On a screen taller than 16:9 the game keeps its 16:9 horizontal view and shows more above and below (Vert+: at 16:10 the 55-degree vertical view becomes about 60). Fullscreen lists every resolution the display offers; pick the display's own (1280x800 on the Deck).
- **Steam Deck.** Set the launch options to `WINEDLLOVERRIDES="xinput1_3=n,b" %command%`. The controller now works under Proton (1.1.0 left it dead while the keyboard worked). In fullscreen, turn on "Disable Frame Limit" in the performance overlay and set `FPSLimit`: the mod's cap then holds, and the Deck's own limiter, which adds input lag, stays off.
- **Other DLL names.** The DLL also works as `dxgi.dll` or `dinput8.dll` (Windows only) when `xinput1_3.dll` is taken by another mod. If another mod needs the same name (for example ReShade as `dxgi.dll`), rename that mod's DLL and set `ChainDll` in `[Loader]`, and both run. A second copy of the mod under another name only passes calls on.
- **A more useful log.** `DS2-FPS-Unlock.log` names the DLL the mod was loaded as, the build, Wine/Proton, the XInput library and each controller as it connects, the display mode and the resolution to choose, and details for a game build whose code the mod cannot find.

## Install
Copy both files next to the game exe, and replace the INI when updating from 1.1.0: it has new keys and the new `[Display]` and `[Loader]` sections. Set `FPSLimit` to the cap you want and `PhysicsFPS` to the rate you actually run at (default 120). `FPSUnlock = false` leaves the frame rate and gameplay unchanged.

## Known limits
Most of the HUD and the FMV videos are not Vert+: they stay the shape the game draws them. Wider screens (21:9) also fill, but that has not been checked in game. Cloth speed is corrected, but the cloth simulation is not identical to 60 FPS. Online play against 60 FPS players seems fine, but it is not guaranteed to match. See the README. Send `DS2-FPS-Unlock.log` with bug reports.

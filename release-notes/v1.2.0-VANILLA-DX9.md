# Dark Souls II (Vanilla), FPS Unlock v1.2.0

High-FPS unlock with gameplay physics fixes. Files: `xinput1_3.dll` and `DS2-FPS-Unlock.ini`, next to `DarkSoulsII.exe`. This is the 32-bit DirectX 9 build for the original Dark Souls II; Scholar of the First Sin uses the Scholar (DX11) release.

## New in 1.2.0
- **A built-in frame cap** (`FPSLimit`, default 0 = uncapped). RTSS or the NVIDIA control panel are no longer needed. The gameplay fixes step at the capped rate, a frame that already ran long is not delayed, and a hitch does not make the next frames rush. `FPSLimitPoint` chooses where the cap waits:
  - `early` (default): at the start of the frame, where the game's own 60 FPS wait was, before the controller is read. The best input response at the cap, but frame pacing can be less even. Also the better choice on a variable refresh rate (VRR) display.
  - `present`: just before the picture is shown. The steadiest frame pacing, with a little more input delay.
- **Fullscreen refresh rate and VSync.** Fullscreen asks for your desktop's refresh rate (`FullscreenRefreshRate`, 0 = the desktop's) and presents without waiting, as before. `VSync = true` waits for one vblank at that rate instead: tear-free, with the frame rate following the screen unless `FPSLimit` is lower. If the display refuses that mode, the game's own refresh rate is tried, then presenting without waiting, then the game's own settings.
- **16:10 and other screens fill in fullscreen** (`FixAspect`, on by default, works with or without `FPSUnlock`). Fullscreen used to draw a 16:9 picture between black bars. It now fills the screen as a window does, with the HUD at its usual size at the screen edges. On a screen taller than 16:9 the game keeps its 16:9 horizontal view and shows more above and below (Vert+: at 16:10 the 55-degree vertical view becomes about 60). Fullscreen lists every resolution the display offers; pick the display's own (1280x800 on the Deck).
- **Steam Deck.** Set the launch options to `WINEDLLOVERRIDES="xinput1_3=n,b" %command%`. The controller now works under Proton (1.1.0 left it dead while the keyboard worked). Turn on "Disable Frame Limit" in the performance overlay and set `FPSLimit`: the mod's cap then holds, and the Deck's own limiter, which adds input lag, stays off.
- **Other DLL names.** The DLL also works as `d3d9.dll` or `dinput8.dll` (Windows only) when `xinput1_3.dll` is taken by another mod. If another mod needs the same name, rename that mod's DLL and set `ChainDll` in `[Loader]`, and both run. A second copy of the mod under another name only passes calls on.
- **A more useful log.** `DS2-FPS-Unlock.log` names the DLL the mod was loaded as, the build, Wine/Proton, the XInput library and each controller as it connects, the display mode, the resolution to choose and the fullscreen game area, and details for a game build whose code the mod cannot find.

## Install
Copy both files next to the game exe, and replace the INI when updating from 1.1.0: it has new keys and the new `[Display]` and `[Loader]` sections. Set `FPSLimit` to the cap you want and `PhysicsFPS` to the rate you actually run at (default 120). `FPSUnlock = false` leaves the frame rate and gameplay unchanged.

## Known limits
The unlocked picture is fullscreen only; in windowed mode the counter can run ahead of the image, which stays at 60. Motion blur and camera motion blur leave ghosting trails while the FPS unlock is on: turn both off in the game's video options. Lighting can flicker at aspect ratios far from 16:9 (seen at 9:16 with the display in portrait; 16:10 does not flicker). Most of the HUD and the FMV videos are not Vert+: they stay the shape the game draws them. Cloth speed is corrected, but the cloth simulation is not identical to 60 FPS. Online play against 60 FPS players seems fine, but it is not guaranteed to match. See the README. Send `DS2-FPS-Unlock.log` with bug reports.
